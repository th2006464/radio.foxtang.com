# UI 与点阵地球实现经验（产品视觉基线）

本文件是复刻迭代中确认的设计决策与踩坑记录，优先级高于早期的演示稿。

## 1. 视觉系统
- 页面品牌：`Radio`。不显示「Foxtang」文字；左上角与 favicon 使用 `https://logo.foxtang.com/avatars-512/set-05/media.png`。
- Logo 应使用 `object-fit: contain`，桌面建议约 **34×34 CSS px**，手机约 **30×30 CSS px**，不拉伸、不叠白色方框。
- 背景为极深墨绿（当前 `#101f1d` / `#101e1b`），主文案偏暖白，辅助字为鼠尾草灰，重要操作按钮为珊瑚橙（约 `#f76e4e`）；网页不能变成普通蓝色卫星地球 UI。
- 桌面：左上品牌；左下电台标题、地区/码率、按钮横排；中右是**超出视口的大地球**。高度 700px 以下收紧行距，避免播放器遮挡。
- 手机：Logo 靠左、光点地球位于视觉中央，标题与大按钮下移并保留底部来源；移动端可拖拽地球，不应因页面覆盖层导致手势被拦截。
- 绝不重新出现陶渊明引文/《桃花源记》或原站品牌；播放与首页文案必须根据真实电台资料变动。

## 2. 一颗地球的正确实现
**不要把首页 Canvas 点云与收听时的 NASA 卫星照片当成两颗地球。** 两个视图调用同一个 `GlobeRenderer.render(lon,lat,cx,cy,radius,t)`：
- WebGL 顶点阶段绘制全屏两三角形；片元着色器从每个屏幕点 `(pixel-center)/radius` 反算可见球面法线。
- `latitude`/`longitude` 从法线及球体 yaw/pitch 得出，经纬转为 equirectangular `uv`。
- `earth.webp` 用于估算 land intensity，依据 UV 网格内的圆形距离、hash 随机度生成细密点；暗海洋、亮陆地、晨昏方向 grazing light 和球缘 limb halo 共用同一张片元材质。
- 球面外部仅处理很淡的光晕；避免硬白色外圈和不透明蓝色海面。

## 3. 相机、手势与地理位置
- 状态：`introRotation`, `introTilt`, `rotation`, `tilt`, `zoom`；进入监听时继承首页角度，不调用 `reset` 造成跳变。
- 桌面首页大地球半径参考 `min(w*.43,h*.92,1050)`；手机采用更小、靠上的中心点。探索时 `globeTransition` 用约 780ms 缓动将同一个球体放大。
- `pointerdown` 记录初始坐标及时间；超过小阈值才识别拖动；水平更新 yaw、垂直更新 pitch 并限制极区；松开按速度阻尼惯性，轻点地球不跳页。
- 相机定位：`projectGlobe(lat,lon,rotation,tilt)` 做可见半球投影；`nearestLongitude` 走最短旋转方向；`focus` 将真实电台坐标缓动至画面中心。
- 选中电台才绘制高亮圆环与名称；城市、省份、国家只允许使用 Radio Browser 已返回的真实字段。
- 鼠标滚轮缩放限定倍率，手机 `touch-action:none` 用于 Canvas 区域，避免 Safari 拖动被页面滚动截获。

## 4. 已遇到的反例
1. **两种地球材质**：首页光点、播放卫星图，视觉不连续。解决：单一 shader / 单套坐标。
2. **首页拖动修改了隐藏星图参数**：UI 没反应。解决：手势在 landing 分支直接更新 `introRotation/introTilt`。
3. **手机黑屏**：WebGL 上下文失败时直接中断初始化，以及 2D fallback 等待 `earth.webp` 生成点数据。解决：捕获异常、Apple 移动端直接选择 Canvas2D、同步生成基础点阵。
4. **盲目认为 CI=实机通过**：测试只覆盖算法和文件布局。解决：区分自动化绿灯、移动端模拟、真机 Safari 和实际广播播放。
5. **误把电台采样数写成全球总数**：API 是分页/镜像数据，标签数量仅应计算已加载筛选后的可用记录。

## 5. 保留功能的边界
删除的是“音乐星图模式”，**不是**背景中装饰性的星点、真实电台点、音乐类型筛选、收藏或位置标签。未来新增新 UI 应优先复用同一 `Universe` 实例，并配套截图基线与交互测试。
